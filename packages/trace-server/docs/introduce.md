# TraceFlow 全链路埋点监控平台

TraceFlow 是一个面向前端、后端和管理端的全链路埋点与监控平台，用于采集、分析和展示用户行为数据。

## 技术栈

| 技术分类   | 技术名称     | 说明                                                                                                             |
| ---------- | ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 服务框架   | NestJS       |
| 开发语言   | TypeScript   |
| ORM 工具   | Prisma       | 类型安全数据库工具，自动生成数据模型、支持联表查询与数据迁移，适配埋点数据 CRUD、聚合统计及多表关联场景          |
| 数据库     | MySQL 8.0    |
| 缓存中间件 | Redis        | 用于埋点数据去重、接口限流、热点数据缓存、JWT Token 存储、BullMQ 任务队列持久化，提升接口响应速度                |
| 任务队列   | BullMQ       | 基于 Redis 实现，处理埋点批量清洗、定时聚合统计、离线 AI 分析、告警推送等异步任务，避免阻塞主流程                |
| 数据校验   | AJV          | 基于 JSON Schema 做埋点上报数据全量格式校验，拦截非法数据、异常格式数据，保障数据质量                            |
| 设备解析   | ua-parser-js | 解析用户设备信息（浏览器类型及版本、操作系统、机型），丰富埋点数据维度，支撑设备分布统计                         |
| 地理解析   | ip2region    | 解析客户端 IP 归属地（国家、省份、城市），用于地域分布统计与异常访问识别                                         |
| 容器部署   | Docker       | 容器化打包，保证开发、测试、生产环境一致性，支持快速扩容、部署与运维管理                                         |
| AI 框架    | LangChain    | 大模型应用编排框架，对接通义、豆包等大模型，实现自然语言查库、RAG 检索、Agent 智能异常分析，适配埋点数据分析场景 |

## 接口通用规范

- 版本前缀：`/api/v1`
- 时间格式：请求与响应中所有时间均使用 UTC 毫秒时间戳 (BIGINT)，避免时区混乱。
- 分页规范：
  - 统一入参：`pageNum`(默认 1)、`pageSize`(默认 10)
  - 统一出参：`total`、`pages`
- 业务强约束：
  - 埋点明细查询接口：强制校验 `startTime/endTime` 为必填，无参数直接返回 400
  - 单条上报、批量上报接口：`msgId` 为必填字段

### 统一响应格式

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {},
  "requestId": "a1b2c3d4-e5f6-7890-abcd-1234567890ab"
}
### 状态码说明
状态码	含义
200	业务处理成功
400	参数校验失败
401	未登录或 Token 失效
403	权限不足
404	资源不存在
429	请求限流
500	服务器内部错误
```
